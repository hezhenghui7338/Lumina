# 问书库 v1

2026-10-29。范围：书库元数据查询与标签整理。此前的阅读知识库方案搁置。

## 入口和交互

macOS 书架工具栏的“问书库”打开轻量窗口，显示问题、实际查询条件、总数和书籍列表。可继续问“其中哪些还没开始读”，也可重新开始。结果卡片点击书名回到阅读器；不建立独立聊天中心，不读取正文或个人评论内容。

主要支持语言、作者、书名、段数、分类、标签、加入时间、最近打开时间、摘要状态、阅读位置进度、划线/评论数量、评分和收藏的筛选与排序。出版年份仅使用已有明确元数据，缺失则未知；简介仅展示已保存的 description 或书籍简介总结句，不调用 LLM 扩写。

结果里可输入标签并预览添加/移除，也可自然语言提出同样操作。预览展示命中总数和书籍列表，点击“应用标签”才写入。管理标签支持创建、改名、删除和查看该标签下的书籍。删除标签不删除书。书架卡片和列表展示已设置的标签，标签应用或更名后自动刷新。

打开次数从功能启用后累计，代表打开书籍的次数；阅读进度是当前位置估算，不声称等同于实际阅读量。阅读状态、进度口径与已有书架一致，不使用可能变为 summarized 的处理状态判断是否读完；单段书打开后不会自动判为已读完。兴趣问题仅用划线、评论等可见指标辅助排序，不建立兴趣画像。

## 实现

- `library_assistant.py`：受约束的 Pydantic 查询计划、参数化 SQL、真实统计、标签与结果快照。
- `api/library_routes.py`：`/library/ask`、结果操作预览/应用及标签 CRUD。
- `AskLibraryView.swift`：输入、结果、连续筛选与标签管理；通过现有 CoreClient 通信。
- 在现有 SQLite 中增加 `library_tags / library_book_tags / library_reading_stats / library_query_results`，初始化幂等。
- 常见数量问题走严格模板，无需模型；其他问题由现有 chat 资源解析成 schema 中的字段、操作符和排序。模型不接收书籍全文、评论正文或整份书库，也不直接生成 SQL、统计答案或修改数据库。
- 后端只接受允许的元数据字段和比较操作；超出范围的内容问题返回能力说明。复杂 OR/分组查询不在首版。
- SQLite 查询在线程中执行，模型调用期间不持有数据库锁。

## 连续筛选与操作一致性

每次查询冻结完整命中 ID 集合，返回不透明 result ID。后续问题明确指代“其中/这些书”时，只在该集合继续查询；独立问题查询全书库。

结果快照有效期 12 小时，过期后提示重新查询。界面最多展示前 100 本，始终展示完整总数；标签应用对象为完整结果集合，界面说明这一点，可以继续筛选缩小范围。

标签操作只作用于预览中的 ID，事务执行并记录应用结果；重复提交返回同一结果。预览后书籍被删除或既有标签被改名/删除时，拒绝应用并提示重新预览。标签删除与书籍删除会清理关联；普通查询不修改书籍或标签。

## 验证

新增后端测试覆盖：语言地区码、300 段边界、作者与划线/评论计数、连续筛选、标签预览不写入、批量应用幂等、改名/删除、过期结果、参数注入、禁止字段、打开次数、缺失年份、超过 100 本的操作范围、API 合同和数据库重新初始化。

人工体验重点：书架打开入口；问英文书数量；查询作者后继续筛选；为结果预览并应用标签；改名和删除标签；点击书名进入阅读器。模型自由表达的理解效果需要实际配置的 chat 资源体验验证，mock 测试不替代真实模型效果评估。
