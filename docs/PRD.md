# Lumina 需求文档（PRD v1.0）

**产品名**：Lumina  
**一句话**：Local AI Reading Companion · AI 伴读  
**标语**：让阅读速度提升 5 倍，而理解深度提升 10 倍。  
**定位三词**：**Local First · 深度理解 · 读得完**

**版本范围**：本文档定义 **v1.0（Mac MVP）** 的产品需求。  
**孵化来源**：LocalAgent `summarize` / `news` 能力；独立产品，独立重写，不依赖 LA 代码。  
**参考**：[product-plan.md](../product-plan.md) · [LocalAgent PRD](https://github.com/vedas-dixit/LocalAgent/blob/main/docs/PRD.md) · NotebookLM · ChatDoc

---

## 0. 核心定位

Lumina 帮你读那些买了、下了、却迟迟没打开的书。

书在本地，模型默认也在本地——不绑 API，也能把一本厚书一段段读完。摘要帮你快进，原文随时可查，下方直接提问。古文、外文书会自动译成你设定的语言，不用另开翻译 App。问问题的时候，该查书查书，该上网查也会上网查——把一件事答完整。

| 词 | 含义 | 不是 |
|----|------|------|
| **Local First** | 默认 Ollama 本机跑通书库全流程；书、笔记、段缓存存本机；外部 API / 联网搜索为可选增强 | 拒绝一切联网；声称推理零外传 |
| **深度理解** | 分段摘要 + 深聊 + 自动翻译 + 笔记 + 段级溯源，理解可验证 | 一次性全文摘要糊弄过去 |
| **读得完** | 产品目标是帮用户完成阅读理解，长书靠分段 + prefetch 逐段推进 | 替代阅读；只追求速度不追求理解 |

**v1.0 平台**：macOS（Apple Silicon 优先，Intel 尽力兼容）。  
**商业模式**：免费开源。  
**与 LocalAgent 关系**：算法与设计参考 LA；代码独立演进；不做 CLI 集成。

## 1. 章程（Constitution）

0. **永不卡住用户（最高原则）**：任何导入、摘要、OCR、联网、切书、深聊都不得冻结 UI；后台可慢，前台必须可点、可取消、可离开。全屏 blocking spinner 禁止；局部 skeleton / 进度可接受。
1. **Local First**：档案存本机；默认 Ollama 零账单完成核心闭环。
2. **读得完**：帮用户读完理解，不是替代阅读。
3. **分段即产品**：长文体验 = 段列表 + 段摘要 + 段深聊，不是一次性吞全书。
4. **笔记即记忆**：读书笔记是 Lumina 的记忆层；v1.0 支持跨书 recall。
5. **可验证**：AI 回答必须可溯源；v1.0 段级 citation，点击即跳转。
6. **源约束**：深聊以文档内容为主要依据；文档未覆盖处如实说明；联网结果与文档 citation 区分标注。
7. **少即是多**：功能可以全做，默认界面只暴露必要操作；核心路径打磨到极其丝滑。
8. **界面即产品**：赏心悦目是核心竞争力；**浅色为默认主界面**；排版、动效、等待态与 AI 能力同等重要。
9. **只摘低垂成熟的果实**：不引入过重栈；本地能完整跑通优先于功能堆砌。

## 3. 信息架构与页面流

### 3.1 应用结构

```
Lumina
├── 书库（默认 Tab）
│   ├── 智能集合：最近 · 未摘要/分段中/摘要中/已摘要/导入失败 · 未读/在读/已读完 · 分类 · 收藏
│   ├── 书架详览（网格/列表 · 排序含段落数与阅读进度，可升序/降序 · 库内书名筛选）
│   ├── 导入（拖拽 / 选择文件 / 选择文件夹）
│   ├── 全部笔记（工具栏 · 跨书列表 · 点击跳转原书原段）
│   └── 书籍卡片 → 阅读器（阅读中侧栏为最近列表，可返回书架）
├── 资讯（独立 Tab）
│   ├── 源管理
│   ├── 同步
│   └── 简报列表 → 精读视图（复用阅读组件）
├── ⌘K 全局搜索（跨书 recall + 跳转）
└── 设置（极简）
    ├── Lumina 引擎（状态 · 停止 · 重启）
    ├── Ollama 连接与模型
    ├── 默认目标语言
    ├── 可选 API Key / 联网搜索
    └── 使用指南（可再打开；macOS 另有 Help 菜单；非顶层 Tab）
```

### 3.2 阅读器布局（段视图 · v1.0）

**布局原则**：阅读默认**沉浸全宽**（段内容占满 detail）；点击空白 → 同步显隐顶部操作栏与底部功能栏（不占段内容宽度）。顶栏管书：书架、摘要/原文、听、搜索、摘要、分段、导出、导入。听 / 搜索 / 摘要 / 分段 / 导出 / 导入为**图标 + tooltip**，菜单项仍为文字。顶栏**中间**展示当前书名（长名单行省略）；**点击书名返回书架**（与左侧「书架」入口并存；v1.0 仅 macOS）。底栏管阅读功能：段列表、笔记、深聊、显示。点击图标才展开对应 panel。右侧段内容支持 **摘要模式 / 原文模式** 切换（顶栏 SegmentedControl 或 `⌘⇧O`），**按书记忆**上次选择。默认 **摘要模式**：展示段摘要（无摘要时显示状态占位），原文 / 译文经「展开原文」按需显示。**原文模式**：连续展示全书原文（外文书含译文），摘要默认收起、可按段「展开摘要」。深聊、笔记为渐进披露抽屉。播放听文本时迷你条始终可见（chrome 隐藏时也保留）。

```
┌────────────────────────────────────────────────────────────┐
│  书架  [摘要|原文]  听  搜索   《书名…》   摘要  分段  导出  导入 │
├────────────────────────────────────────────────────────────┤
│                                                            │
│              段摘要 + 「展开原文」                          │
│                                                            │
├────────────────────────────────────────────────────────────┤
│           段列表   笔记   深聊   显示       ← 底栏          │
└────────────────────────────────────────────────────────────┘

点击空白 → 同步显隐顶栏 + 底栏（段内容仍全宽；两栏 overlay，恒定预留高度，正文不位移）
点击底栏 → 段列表自底上滑（停在底栏之上） / 笔记抽屉 / 深聊抽屉
再次点击空白 → 收起两栏及抽屉（段列表再点底栏图标或 Esc）
点遮罩 · Esc → 收回笔记 / 深聊（保留两栏）；段列表打开时 Esc 先收回目录
```

**段列表信息密度（对比 LocalAgent 改进）**

LocalAgent 段列表只有段序号 + 摘要首句，信息太少。Lumina 段列表每项应呈现：

| 层级 | 展示内容 | 示例 |
|------|----------|------|
| **结构树（最多 3 层）** | 按原文部/章嵌套；点标题折叠/展开；无结构则平铺 | 第一部分 → 第一章 → 段 |
| **段标签** | 第一行仅段序号 + 浓缩标题；分组后行内不再重复章名 | `段 5 · 孔子论学而时习` |
| **可选副标** | 页码范围 | `p.42–48` |
| **状态** | ● 当前 · ✓ 已读 · ◐ 生成中 | |

> 结构树标题最多 2 层（部/卷 + 章）；节并入所属章。叶子永远是产品段。第一行：分组后为 `段 N · label`（无 label 时仅 `段 N`）；无章节结构的平铺列表用 `label`（无则仅 `段 N`）。第一行不含「等待摘要…」等状态文案。摘要预览与要点标签仍在标题下方。

**渐进披露**

| 元素 | 触发方式 | 行为 |
|------|----------|------|
| 顶栏 + 底栏 | **点击段内容空白** | 顶部操作栏（书操作）+ 底部功能栏（段列表 / 笔记 / 深聊 / 显示）；**段内容仍全宽**；两栏 overlay 且恒定预留高度，显隐不得位移正文；再次空白点击全部收起 |
| 段列表 | 底栏「段列表」 | 自底上滑覆盖阅读区（停在底栏之上，不挤压、不盖住底栏）；再点段列表 / Esc / **选段后关闭**回到阅读；打开笔记或深聊时关掉目录 |
| 书库 | 未选书：左智能集合 + 右书架详览；阅读中无「最近」列表；「书架」与顶栏中间书名均可返回浏览（书名长则省略；v1.0 书名入口仅 macOS） | 阅读沉浸时 detail 全宽 |
| 深聊 | 底栏「深聊」 / 摘要 follow-up | 底部抽屉，停在底栏之上；唤起后输入框可见并聚焦 |
| 笔记 | 底栏「笔记」 / 选区「存为笔记」 | 右侧抽屉，上下让开顶底栏 |
| 显示 | 底栏「显示」 | popover：五档字号（与资讯共用）+ 四色纸（白 / 象牙 / 护眼 / 夜间）；只涂阅读正文，不改设置里的浅/暗色 |
| 导出 | 菜单 · 阅读器更多 | 非主界面常驻 |
| 书内原文搜索 | 顶栏搜索 / `⌘F` | 只搜该书 `raw_text`；命中后切原文模式、跳段、高亮匹配并滚到可见；上一条 / 下一条 |
| 跨书搜索 | `⌘K` | 全局浮层（笔记 + 段摘要 + 书名；不是书内原文查找） |

### 3.3 书籍视图（全书级 · 待设计）

- 全书摘要卡 + 章节大纲树
- 阅读进度可视化（书架卡片与智能集合展示未读/在读/已读完；全书目录视图仍待设计）
- 从全书视图一键跳入某章/某段

### 3.4 黄金路径 Onboarding（首次 spotlight）

**激活路径**仍是三步：**导入 → 打开书 → 点摘要**（不必在引导里当场做完）。

**首次启动**在真实界面上逐项高亮（spotlight），不拦引擎启动、不拦书库点击。全程可「跳过引导」。点「知道了」或跳过后不再出现。

| 步 | 说明 | 高亮 |
|----|------|------|
| 1 | 导入书籍 | 书库空态「导入书籍」；已有书则书架区（并提示右上角导入） |
| 2 | 选择书籍阅读 | 书架 / 第一张书卡 |
| 3 | 配置摘要 API | 自动切到设置，高亮 API 资源（本机 Ollama 或外部 Key 都算配好） |
| 4 | 点击摘要 | 阅读器顶栏摘要 |
| 5 | 切换摘要与原文 | 顶栏「摘要 \| 原文」 |
| 6 | 深聊 | 底栏深聊 |
| 7 | 笔记 | 底栏笔记；主按钮为「知道了」 |

空书架时 4–7 合为一步：仍停在书架，说明打开书后顶栏可摘要/切换、底栏可深聊和笔记，然后「知道了」。不内置样书。

Ollama 检测 / 安装 / 拉模型只在 **设置 → API 资源 → Ollama 编辑页**，不占首启引导。

spotlight 结束或跳过后展示 **使用指南**（7 条日常操作：导入、阅读 chrome、摘要/原文、听、深聊、查找、开始摘要）。设置「关于」与 macOS Help 可再打开同一份，**不得**清掉首次完成标记、**不得**重跑 spotlight。Windows 无 Help 菜单，设置「关于」打开同一份对话框。

不做：设置里「重新显示 spotlight」、资讯 Tab 引导。安装与签名拦截仍走 README。

## 4. 设计规格

### 4.1 视觉方向

**参考调性**：Apple Books 阅读舒适度 · Linear 界面克制 · Readwise 书库清晰。

| 要素 | v1.0 规范 |
|------|-----------|
| **主题** | **浅色为默认与主推**；暗色模式完整支持，设置中可切换。阅读器另有四色纸（白 / 象牙 / 护眼 / 夜间），只改阅读面，**不是** App 浅/暗色 |
| **字体** | 正文：系统中文栈（PingFang SC / SF Pro）；**段摘要总结**：较大可读正文字号（约 18–20pt）、主色、宽松行距；**结构化要点**：`.body` 级、按条拆解；锚点与分区标题为次要色小字。阅读与资讯共用五档字号，底栏「显示」调节 |
| **间距** | 8pt 网格；总结与结构化要点之间留白 + 细分隔；段摘要与原文之间明确分隔；深聊区与段内容区视觉分隔清晰 |
| **栏宽** | 正文随可用区域铺满（参考微信读书），仅保留左右内边距，不人为限宽 |
| **圆角** | 卡片 12pt；输入框 12pt |
| **强调色** | 单一品牌 accent（待定，建议暖琥珀/书页金，与「Lumina」呼应） |
| **整体气质** | 书页感、留白、低对比边框；避免「工具软件」的密集控件感 |

> 高保真稿产出：`docs/design/`（PRD 确认后并行绘制）

### 4.2 动效原则

| 场景 | 要求 |
|------|------|
| 段切换 | ≤200ms crossfade；无白屏 |
| 深聊区滚动 | 新消息自动滚底；段切换时保留该书对话历史 |
| Citation 点击跳转 | 段列表滚动 + 原文高亮 flash（≤400ms） |
| 摘要生成中 | skeleton shimmer，禁止全屏 blocking spinner |

### 4.3 等待态与 Prefetch

| 场景 | UX |
|------|-----|
| 短书（≤12k 字） | 导入后 ≤30s 呈现首屏摘要 |
| 长书 | **首段就绪即可读**；其余段后台 prefetch；段列表显示进度 ◐ |
| 深聊首 token | 输入框 typing indicator；目标 ≤3s（Ollama 4b 档） |
| Ollama 未连接 | 书库可读；AI 功能灰显 + 引导连接 |

## 5. 功能详述

### 5.1 书库管理

**导入**
- 支持：拖拽文件/文件夹、菜单选择、书库空白区 drop
- 格式：PDF · EPUB · MOBI · AZW/AZW3 · TXT/Markdown · HTML/XHTML · RTF · DOCX · ODT · FB2
- 不支持：DRM 电子书、旧版 DOC、CHM、DJVU；**PNG 图片书（v1.1）**
- **大小限制**：单文件 **>500MB → 警告并拒绝**
- **重复检测**：同 `file_hash` → 弹窗询问**是否覆盖**。批量导入时弹窗另提供 **跳过**（只跳过本书、继续导其余）与 **跳过剩下所有**（跳过本书及后续所有重复书、不再弹窗，**仍导入队列中的新书**）。**取消剩余导入** 停止整批剩余（含尚未导入的新书）。「跳过剩下所有」只对当前这批队列有效，队列清空后下次导入重新询问
- **批量**：10+ 本可同时导入；每本独立后台 job

**元数据**
- 自动提取：标题、作者、封面（有则显示）
- 用户可编辑标题（展示名）；身份与去重仍按 `file_hash`，改书名不影响重复检测

**导入存储（v1.0）**
- 文件**复制**到 `~/Library/Application Support/Lumina/books/{id}/`，不依赖原路径

**组织方式（v1.0 决策）**
- **浏览 / 阅读分离**：未选书时为书架详览（左集合 + 右网格/列表）；点书进入阅读器。阅读中侧栏仅为最近打开短列表。
- **智能集合**（互斥单一维度）：最近（默认）· 未摘要 · 分段中 · 摘要中 · 已摘要 · 导入失败 · 未读 · 在读 · 已读完 · LLM 分类 · 收藏
- **LLM 固定主分类**：文学 · 历史 · 科技 · 哲学 · 经济 · 传记 · 其他（导入后后台自动分类，可右键重新分类或手动纠正）
- **收藏**与**排序**（最近访问 · 添加时间 · 标题 · 段落数 · 阅读进度 · 收藏优先）。排序字段旁可选**升序 / 降序**：标题默认升序（A→Z），其余默认降序（新→旧、多→少、进度高→低、收藏在前）。切换字段时回到该字段默认方向；字段与方向均记忆。收藏优先升序为未收藏在前
- 暂不实现文件夹 / 自由多标签（v1.1 评估）

**阅读进度**
- 记录：当前段序号、最后打开时间（打开书时恢复，切换段时后台保存）
- 书架以智能集合与卡片次要信息展示：未读（从未打开）· 在读 · 已读完（≥2 段且已到最后一段）。不使用 `books.status`（摘要完成后会写成 `summarized`，会盖掉在读）
- 阅读器侧栏不做阅读进度条主视觉

**摘要状态（书级）**
- 书架摘要维：未摘要 · 分段中 · 摘要中 · 已摘要 · 导入失败（卡片/列表徽章同文案）
- **分段中**：导入全过程（提取 / 解析 / OCR / 分段）或整书重新分段进行中
- 分段完成后落到 **未摘要**；若已开「自动开始摘要」则进入 **摘要中**
- **导入失败**：`status=error`（含取消导入）占摘要维独立集合；仍出现在该维「全部」；不占未摘要 / 分段中 / 摘要中 / 已摘要。卡片显示失败原因；可删除后重新导入。v1.0 不提供一键重试、不自动清理
- 手动调整相邻段分界不是整书重新分段，不进入分段中

**摘要进度**
- 书库卡片显示「摘要 ready/total」+ 细进度条
- 阅读器段列表侧栏同逻辑
- 段内容阅读区顶部（摘要未完成、书库收缩且段列表未展开时）显示「摘要 ready/total」+ 细进度条

**导入 / 分段进度**
- 书库卡片与阅读器处理中界面显示阶段文案（解析 / 识别序言与正文结构 / 切分 / 写入）+ 字数或页码细进度条（`page/total`）；第二本等 CPU 锁时显示「排队等待分段…」
- 无进度超过 **3 分钟** → `status=error`，卡片展示失败原因（如「分段超时：超过 3 分钟没有进度」）。OCR 只要仍在报页进度则不误杀。
- 单本 CPU 墙钟：`max(30 分钟, 页数×60 秒, 文件体积 MB×30 秒)`，硬顶 **8 小时**（MB 按 1024² 字节）。PDF/OCR 有页数用页数，否则用文件体积；抽出后的字符数不作启动预算。超时文案带实际上限。可取消、可离开。

**导入限制（v1.0）**
- 单文件 **>500MB → 警告并拒绝**
- 同 `file_hash` 已存在 → 弹窗询问**是否覆盖**；批量冲突可 **跳过剩下所有**（后续重复不再弹窗，新书仍导入）
- 支持 **10+ 本**同时批量导入

**验收**
- 单次导入 ≥10 本混合格式书无 crash
- 封面/标题正确率 ≥90%（有元数据的格式）
- 重复导入正确提示覆盖；批量冲突可选跳过剩下所有而不再弹窗，新书仍导入；超大文件被拒绝

### 5.2 文档摄入与 OCR

**流水线**：文件 → 格式检测 → 文本提取 → OCR（如需）→ 统一纯文本 → 分段

| 格式 | v1.0 最低体验标准 |
|------|-------------------|
| **TXT / Markdown** | `.txt/.text/.md/.markdown/.mdown/.mkd/.log` 直接摄入；编码自动检测（UTF-8 优先） |
| **HTML / XHTML** | 提取正文、标题、作者和标题层级；忽略脚本与样式 |
| **RTF** | 提取纯文本及可用的标题、作者元数据 |
| **DOCX** | 保留段落、标题、表格文本及文档元数据 |
| **ODT** | 保留段落、标题及文档元数据 |
| **FB2** | 保留章节结构及书名、作者元数据 |
| **EPUB** | 章节结构保留；正文完整提取 |
| **PDF** | 有可用文本层直接提取（PyMuPDF 优先，避免 Identity-H CID 乱码）；扫描件或乱码文本层自动 OCR |
| **MOBI / AZW / AZW3** | 正文提取；章节锚点尽力保留。无 DRM 的 KF8（`.azw3`）走现有 MOBI 解包再进 EPUB pipeline；带 DRM 的 Kindle/MOBI 仍拒绝 |

**OCR（本地 RapidOCR + 可选云端视觉 API）**

- 默认引擎：**RapidOCR + PP-OCRv6**（`lumina-core`，参考 LocalAgent `ingest/ocr.py`）
- 可选云端：设置中配置 OpenAI 兼容 Base URL、视觉模型和 API Key；三项完整时云端优先，任一项为空时使用本地 OCR
- 云端请求失败、超时、未授权或额度不足时导入明确失败，**不静默回退本地**，避免用户误判数据处理路径
- 隐私：启用云端 OCR 时逐页上传扫描图像；双端设置页必须明确提示并提供连通性测试
- 扫描 PDF：PyMuPDF 逐页渲染 → OCR → `## [p.N]` 标注文本；文本层覆盖率 < 15% **或 CID/Identity-H 乱码文本层**触发
- 语言：`OCR_LANG=ch` 默认（简中；古文扫描书优先）
- **PNG 图片书**：v1.0 不支持；v1.1 纳入
- 依赖：`rapidocr` + `onnxruntime` + `pymupdf`（打包进 sidecar，用户无感）

> 初版 TDD 曾考虑 Mac Vision.framework；在 Python sidecar 架构下，RapidOCR 与 ingest 一体、中英文质量更好、且 Win 可复用，故采用 LA 同栈方案。

**验收**
- 每种格式至少 2 本真实样本跑通摄入
- 扫描 PDF OCR 后可分段摘要
- 配置完整的云端 OCR 优先于本地；未配置才初始化 RapidOCR；云端错误可见且不会降级

### 5.3 智能分段与摘要

**摘要档位**
- 「摘要」为可见拆分：点文字立刻开始**正常摘要**；只有点右侧系统箭头才展开高级项，确认后再跑。悬停文字不得弹出高级。不用星号。默认正常。
- 阅读器下拉三项：（1）**开始摘要**点文字即 `start` 正常档、不另确认；箭头「高级摘要（仅未摘要）」确认后高级档。（2）**重新摘要整书**点文字或箭头高级项都先弹出覆盖全书确认，取消不发请求。（3）**停止摘要**直接停止。
- 书架工具栏两项：**全部开始摘要**（同上拆分）+ **全部停止摘要**。多选栏同结构。
- 段内「生成摘要」仍为左键正常、右键高级。书籍右键与任务页保持并列项。
- 设置中的每个 API 资源分别配置正常模型与高级模型，两档共用 summarize 资源优先级链；某资源未配置高级模型时回退其正常模型。
- 「开始摘要」切换档位只作用于尚未摘要（pending / error / failed）的段落；已有摘要保留原档位，不覆盖。
- 「全书重新摘要」才会按所选档位覆盖全书已有摘要。该操作消耗大量计算与 API 资源，双端必须先弹出确认；用户取消则不发请求。
- 任务可停止、可离开页面，切换档位不得阻塞 UI。

**分段档位**
- 导入与整书重新分段可选择「正常分段 / 高级分段」，默认正常。设置中的「导入默认分段」控制新书导入档位。
- **正常**：先建结构树（部/章 HARD，节 STRONG；PDF 页码只作锚点），再在章内按整段自然段打包到 hard max；切点阶梯为章/角色 > 自然段 > 句号 > 语义。有 embedding 时只在段界上提前停，并保留文档地图 LLM。
- **高级**：同上，再对超长或无标点块用模型给出切点（offset 先吸附到段，再句）。该档消耗更多计算，双端必须先确认。
- 段是阅读/摘要/引用单元：`join(raw_text) == 原文`，禁止 overlap / skip-window。同一章内每段不少于 200 字；章标题须并入本章后续正文。整章 / 全书不足 200 字时允许短段。短章不得为填地板而吞下一章。

**分段**
- 结构树优先于字数；章内按自然段打包，未超 max 的自然段不劈开。同一章内每段不少于 200 字（章标题并入本章后文）；整章或全书不足 200 字时允许短段，仍不得吞下一章。Ollama 默认目标 2000 字（上限 3000）；OpenRouter 3500 / 5250；其他云端 4000 / 6000。设置页与整书重新分段的目标字数可手输（范围 200–8000；Ollama 设置上限 4000），并提供 500 / 1000 / 1500 / 2000 / 2500 五档快捷应用。
- 每段保留锚点：章节名、页码（PDF）、段序号
- **手动调整分界**：顶栏「分段」图标点一下只打开菜单（「调整分段」「整书重新分段」），再点菜单项才执行。进入调整后展示相邻两段拼接原文；用户点击某一处作为新分界（吸附句末/段落/章节标记），高亮预览新切点，不立即落库。点「保存」才保存；取消不发请求。只改切点、保留段 UUID 与笔记；被改动的两段作废摘要与译文并自动重新入队。不再提供拖动分界或上一处/下一处步进。整书「重新分段」仍会清空段绑定数据。导入与整书重新分段期间书级摘要状态为 **分段中**。

**段摘要格式**
- **总结在上**：最多三句话概述（能一句说清就一句）；字号大于正文次要层，主色、宽松行距，作为首屏阅读焦点
- **结构化要点在下**：3–7 条按条拆解；每条 `{label, body}`，label ≤8 字作扫读索引，body 1–2 句充实说明（40–120 字），标签视觉加重
- **需要注意**（可选）：0–3 条，仅在有局限、免责、反方观点时出现
- **你可以接着问**：2–3 个引导问题，基于本段已覆盖内容；可点击一键发起深聊
- 锚点标注：`〔§章节名 · 段 N · p.页码〕`，展示于摘要顶栏次要色
- **人称**：原文自称「我」（含英文 I）时，总结与要点直接用第一人称转述（我如何如何），不得改写成「叙述者」；仍禁止把「我」写成阅读助手 / AI / 读者。第三人称原文保持他 / 她 / 主角，不得硬改成「我」

**段摘要质量监督**
- 摘要入库前先做本地可解释检查，识别乱码、模板残留、占位文本、明显截断与机械重复；可疑摘要再由独立一次模型调用对照原文复核。
- 原文自称「我」而摘要写成「叙述者」时，视为质量问题并自动重摘要（单处即重生，不等第二个缺陷）。
- 同一候选摘要出现 **超过 1 个独立的乱码或表意不清问题**时，不向用户展示，自动进入下一轮摘要生成。
- 重摘要 prompt 必须列出上轮问题所在字段、原因和短片段，要求逐项改进；单处轻微问题不触发自动重摘要。
- 摘要 prompt 注入受预算限制的「上一章摘要 + 本章已生成摘要」，仅用于人物、代词、时间线和因果消歧；当前段没有明确依据时不得擅自合并人物身份。
- 质量监督运行在后台摘要 job 内，复用并发限制、取消与 SSE 进度，不得冻结或阻塞阅读 UI。
- v1.0 此门仅覆盖书籍段摘要；资讯精读的 Markdown 摘要仍走人工语义抽检。

**段摘要阅读 UI（对齐 LocalAgent 速读卡层次）**

```
〔§章节 · 段 N〕
总结
  …较大字号的 1–3 句散文…
────────
结构化要点
  │ 标签
  │ 充实正文……
  │ …
────────
需要注意（可选）
  · …
────────
你可以接着问
  [可点击引导问题]
原文（次要层级）
```

**Prefetch 策略（v1.0）**
1. **导入完成即分段**入库；段摘要 prefetch **默认关闭**（设置「自动开始摘要」可开；开启后导入/打开书/重启即 prefetch）
2. 开启自动摘要时：同一本书按段 0…N 顺序生成，保证前文背景可用；不同书之间仍可并行
3. 段摘要磁盘缓存；`file_hash` 未变则跳过重复生成
4. 用户打开书：若段已 ready → 直接呈现；否则 skeleton + SSE 等待（或手动开始摘要）
5. 用户跳到未 prefetch 段 → 继续该书摘要链，但不越过尚未完成的前序段
6. 段摘要失败：重试 3 次 → `failed`；最终失败后继续下一段，段列表可手动重试

**段列表 UI（v1.0 决策：信息密度提升）**

LocalAgent 段列表仅显示段序号，信息太少。Lumina 段列表应让用户**不点进去也能判断这段讲什么**：

| 层级 | 展示内容 |
|------|----------|
| **结构树** | 最多 3 层：部/卷 + 章 + 产品段叶子；节并入所属章。点标题只折叠/展开（不关目录）；点段选段并关闭覆盖层。默认全部展开 |
| **段条目** | 第一行：`段 N · 标题`；其下可有摘要预览与要点标签 |
| **状态** | ● 当前 · ✓ 已读 · ◐ 生成中 · ○ 未生成 |

**行标题来源**
- 有章节结构（分组）：第一行为 `段 N · label`；章名只出现在结构树标题，不在每段重复
- 无章节结构（平铺）：第一行用 `label`（≤20 字）
- 未摘要且无可用标题时第一行可以只有 `段 N`
- 第一行不含摘要状态文案；状态用左侧图标
- `label` 仍随摘要生成，供无章名导航及笔记 / 深聊使用

**示例**
```
序言
  段 1  ●  引子：主角出身寒门
  段 2  ✓  科举之路起笔
第一部分
  第一章
    段 3  ◐  入京夜谈
    段 4  ○
  第二章
第二部分
```

无章节结构时保持平铺段列表。叶子永远是产品段（chunk），不是原文自然段。不是 §3.3 全书级视图。

**验收**
- 有结构时段列表按原文嵌套（最多 3 层）；分组后段行为 `段 N · label`，章名只在结构树标题
- 未摘要且无章名时允许仅 `段 N`；折叠标题不关闭目录
- 100 万字书：首段 ≤15s 可读（Ollama 4b · M 系列 16GB）
- 段切换 ≤200ms（已缓存段）

### 5.3.1 听文本（朗读，不是音视频摄入）

阅读器顶栏在「摘要 | 原文」旁提供 **听**：与当前阅读层对齐，不另开第三种模式。

- **摘要层**：听简要摘要 / 听完整摘要（菜单二选一）；**单击扬声器永远读简要摘要**，听完整必须点 **始终可见的下拉箭头**（禁止依赖长按；不记住上次）
- **原文层**：听原文（外文书 v1 只读原文，不自动读译文）
- **连播**：同模式播完当前段 → 下一段；全书结束停止
- **迷你条**：播放期间始终可见（暂停/继续、倍速 0.8–2、上一段/下一段、关闭）
- **离开阅读器 / 切书**：立刻停止并取消进行中的合成

**朗读稿**（听完整摘要 ≠ 复制全文，且永不朗读「你可以接着问」）：

- 听简要摘要：`sentences` 逐句（屏幕上的「总结」）
- 听完整摘要：总结句 + 「结构化要点」+ `N. {label}。{body}`；不读 `notes` / 「需要注意」
- 听原文：该段 `raw_text`

摘要两种模式禁止为朗读去拉 `raw_text`（走 `GET .../segments/{idx}/summary`）。未就绪段迷你条提示「第 N 段尚无摘要，已跳过」；连续跳过过多则暂停。

**引擎**（播放永远在客户端，完全离线，不产生 TTS API 费用）：

- 只用操作系统已安装的神经语音。macOS 为 `AVSpeechSynthesizer`（优先 Premium / 增强）；Windows 为 `Windows.Media.SpeechSynthesis`（优先 Neural）。
- 设置「听书」列出本机音色并标注「高级 / 增强 / 标准」。未下载高质量语音包时听感接近机械音。设置展示逐步说明，按钮打开系统里**当前版本真正能下载**的页面：macOS 15+ 为**旁白实用工具**（语音 → + → 下载 Premium / 增强，**不必打开旁白朗读**）；macOS 14 及更早为辅助功能 → 朗读内容 → 管理声音；Windows 为时间和语言 → 语音 → **添加语音**（名称含 Neural 的神经语音，不要只下旁白 Natural）。下载由操作系统完成，Lumina **不代下、不内置音库**。
- **不**走云端 `/v1/audio/speech`，不接讯飞等商业离线 SDK，不跑本地大模型 TTS。

**v1 不做**：锁屏后台听、书架迷你播放器、资讯听读、听译文、本地大模型 TTS、云端 TTS。与 §9「音频/视频摘要」区分：那是摄入音视频文件做摘要，本节约是把已有文本/摘要读出来。

**验收**
- 摘要层单击扬声器朗读简要摘要；听完整摘要入口是始终可见的下拉箭头，不依赖长按；不记住上次档位
- 听简要摘要不含要点、notes、follow_ups
- 听完整摘要含要点，不含 notes、follow_ups
- 离开阅读器立即停止
- 朗读不发起外网 TTS 请求；可离线播放

### 5.3.2 阅读器原文搜索（书内 Find）

与 `⌘K` 跨书 recall（§5.6）分开：这里只在**当前打开的书**里找原文，定位到匹配在段内的位置。

**入口**
- 阅读器顶栏搜索图标；点击展开输入框（随顶栏显隐）
- `⌘F`（Windows：`Ctrl+F`）显栏并聚焦输入框
- 上一条 / 下一条；Enter 搜或跳下一条；Esc 先收起查找（高亮清除）

**检索**
- **只搜**段 `raw_text`；不搜译文、段摘要、笔记
- Sidecar 线程执行；UI 不冻结；可继续点别的
- 响应只含段序号、字符偏移、snippet；**禁止**带回 `raw_text`
- 无匹配时提示「无匹配」，不跳转

**定位（Find in page，不是句级 citation）**
- 命中后切换到**原文模式**，跳到该段，在原文中高亮当前匹配并滚到可见
- 同段多命中：上一条 / 下一条只改高亮与滚动，不重搜
- **不是** §5.5 句级/词级引用溯源（§9 仍为 v1.1）；citation 仍整段闪高亮

**验收**
- 查询只命中原文，不因摘要/译文相同字词误跳
- 命中后可见匹配高亮；上一条 / 下一条循环
- 长书搜索期间可取消、可离开、可切书；列表/搜索 API 不含全书原文

### 5.4 自动翻译（用户无感知）

**能力**
- 书籍语言 ≠ 用户目标语言时，**自动 LLM 翻译**并呈现
- v1.0 **不单独做语种检测/古文特殊处理**；统一 LLM pipeline
- 术语在同一本书内保持一致（prompt 约束 + 书级 glossary 缓存）

**交互（v1.0：系统做好，用户不知）**

| 场景 | 行为 |
|------|------|
| 书籍语言 = 用户目标语言 | 展开原文后仅呈现原文 |
| 书籍语言 ≠ 用户目标语言 | 展开原文后**自动呈现译文**（系统默认行为） |

- **无「翻译」按钮或开关**（书详情高级设置除外）
- 导入时即 queue 翻译 job；与摘要 prefetch 并行；优先级低于摘要
- 全书翻译后台逐段完成 + 缓存

**语言设置**
- 全局默认目标语言（设置页；默认跟随系统语言）
- 单本书可 override（书详情 · 语言）

**验收**
- 外文书导入后，用户展开原文时自动显示译文，无需独立翻译入口
- 摘要模式：切换段 ≤200ms（已缓存）；换段后原文恢复为收起
- 原文模式：原文常驻展示；滚动窗口内按需 prefetch 单段原文（列表 API 不含 `raw_text`）；未缓存段 skeleton 占位，UI 不冻结

### 5.5 深聊

**回答逻辑（v1.0 决策：文档 + 联网）**

要把一个问题答好，通常需要两类信息：
1. **文档上下文** — 当前段/全书 RAG 召回的相关段
2. **联网补充** — 背景知识、事实验证、术语解释、延伸阅读

深聊默认**启用**文档检索；联网由**证据充分性（Evidence Sufficiency）**驱动——仅当本地上下文无法支撑高置信回答时，才按意图/领域检索外部源（Wikipedia · DuckDuckGo · arXiv · Open Library · GitHub）。用户可在设置中关闭联网。

**长线程策略**
- **分层索引 + 动态上下文组装（DCA）**：L0 全书总摘要 · L1 分摘要（聚类/章 + 段）· L2 原文证据
- 全书摘要完成后后台将段摘要按章优先打包，递归再摘要，直到一层能塞进单段预算，得到 L0
- 全书提问按 **总摘要 → 分摘要 → 原文** 填满 chat 预算后停止；citation 仍为 `[段 N]`
- 当前段提问以本段原文为主，有 L0 时附一行全书总摘要作背景
- 以摘要导航、原文溯源，支撑全书 thread 连续深聊

**结构化输出**
- LLM **JSON mode**：`{answer, citations, web_refs, evidence_sufficient}`

| 来源 | 标注 | 优先级 |
|------|------|--------|
| 文档段 | `[段 N]` citation，可点击跳转 | 主依据 |
| 联网 | `[网]` + URL / 来源名 | 补充；不与文档 citation 混淆 |
| 文档未覆盖 | 明确说明「书中未提及」 | — |

**源约束**
- 涉及书中内容时，**必须以文档为依据**，附段级 citation
- 文档未覆盖的部分：可结合联网补充，但须标注来源
- 纯文档问题且源中无信息 → 拒答，不编造

**段级引用溯源（v1.0）**
- Citation 格式：`[段 12]` 或 `[§第三章 · 段 5 · p.42]`
- 点击 → 段列表定位 + **整段闪高亮**（~400ms fade-out；非句级 offset）
- 不做句级/词级（v1.1）

**选区提问**
- 原文高亮 → 上下文菜单：解释 · 摘要 · 发送到深聊
- 选区内容自动注入深聊上下文

**对话线程（v1.0）**
- **每本书一个对话线程**；切换段时不新开 thread，新消息自动注入当前段上下文

**联网搜索**
- 书库深聊与资讯深聊**共用同一套逻辑**
- 默认开启；无网络时仅文档模式，UI 提示
- 联网结果不自动写入书库

**验收**
- 10 轮 follow-up 不丢上下文
- Citation 点击 100% 跳到正确段
- 需联网才能答好的问题（如「这个历史事件的背景」），能返回带 `[网]` 标注的回答
- 纯文档问题且源中无信息 → 100% 拒答（测试集）

### 5.6 读书笔记与跨书 Recall

**硬规则**：笔记必须关联指定段落（`segment_id` 必填）。无当前段时不可新建；游离于段落的笔记无意义。

**笔记类型**
| 类型 | 创建方式 |
|------|----------|
| 手动笔记 | 笔记面板输入（挂当前段） |
| 划线 | 原文选区 + 高亮（挂所在段） |
| AI 笔记 | 深聊回答 ·「存为笔记」（挂当前段） |

**书内展示（阅读器右侧抽屉）**
- 默认可看该书全部笔记；可筛「仅当前段」
- 每条展示段标签；点击 → 跳到原段

**书库 · 全部笔记**
- 跨书笔记列表（书名 · 段标签 · 内容）
- 点击 → 打开对应书并跳到原段

**跨书 Recall（v1.0）**
- `⌘K` 全局搜索：笔记 + 段摘要 + 书名
- 结果分组：书籍 · 笔记 · 段
- 点击 → 跳转对应书 + 段（与全部笔记一致）

**验收**
- 无当前段时不可新建手动 / AI 笔记
- 3 本书各 5 条笔记，全部笔记与 `⌘K` 均可搜到并跳到原段
- 书内抽屉点笔记必达原段
- 笔记持久化；重启后仍在且仍挂段

**验收**

- 「仅导出总结」只有各段三句话，无要点 / 注意 / 追问 / 译文 / 笔记

## 6. 数据模型（v1.0）

```
Book
├── id, title, author, format, file_path
├── cover_path?, language?, target_language?
├── segment_count, current_segment_index
├── status: unread | reading | summarized | processing | error
├── summarize_state: idle | segmenting | queued | running | paused | summarized
└── created_at, updated_at

Segment
├── id, book_id, index, chapter?, heading_path?, page_range?
├── raw_text, summary?, translation?, label?  // label: 段列表浓缩标签 ≤20 字
├── heading_path: 部/章标题数组，最多 2 项；段列表组树用
├── summary_status: pending | running | ready | error | failed
└── anchor_label  // 〔§… · 段 N · p.…〕

Note
├── id, book_id, segment_id, quote?, content  // segment_id 必填
├── type: manual | highlight | ai
└── created_at

ChatSession
├── id, book_id, scope: segment | book
├── segment_id?, messages[]
└── updated_at

Citation（运行时）
├── segment_id, label  // [段 12]
└── message_id
```

`summarize_state` 是书架摘要维：`segmenting` = 导入全过程或整书重新分段（此时 `status=processing`）；完成后为 `idle`（未摘要），自动摘要开启则为 `queued` / `running`（摘要中）。`status=error` 为摘要维 **导入失败**（含取消导入），不占用未摘要/分段中/摘要中/已摘要。书架「未读/在读/已读完」按 last_opened_at + 段进度推导，不用 `status`。

**本地存储根目录**：`~/Library/Application Support/Lumina/`（Mac）

## 7. 非功能需求

### 7.1 性能

| 指标 | v1.0 目标 |
|------|-----------|
| 首段摘要（短书） | ≤30s |
| 首段摘要（长书） | ≤15s |
| 段切换 | ≤200ms |
| 深聊首 token | ≤3s（Ollama qwen3.5:4b · 16GB M 系列） |
|  idle 内存 | ≤500MB（不含 Ollama） |

### 7.1.1 响应性（永不卡住）

| 约束 | v1.0 目标 |
|------|-----------|
| UI 可交互 | 导入 / 摘要 / OCR / 联网 / 切书 / 深聊进行中，前台仍可点、可取消、可离开 |
| ≥200ms 操作 | 必须有非阻塞反馈（skeleton / 进度 / 局部状态），禁止全屏 blocking spinner |
| 导入/分段心跳 | 结构扫描与切段须周期性 SSE `ingest_progress`（字数或页）；无进度 3 分钟失败；单本墙钟 `max(30 分钟, 页数×60 秒, 文件 MB×30 秒)` 硬顶 8 小时，超时须写明实际上限 |
| Sidecar 事件循环 | `async` handler 内禁止同步 CPU / 网络 / 大文件 I/O；重活须 `to_thread` 或 JobQueue |
| Sidecar 生命周期 | 应用层拥有 `lumina-core`：退出必杀进程；卡死时 `/health` 超时须换新进程，不得复用；设置可停止/重启 |
| 主线程 | 禁止同步重 I/O；禁止在 MainActor 上解码含全书原文的大体量 JSON |
| 列表 API | 段列表默认不含 `raw_text`；原文按需单段拉取 |

### 7.2 隐私

- 书籍、笔记、段缓存、对话：**仅存本机**
- 选用外部 API / Tavily / ddgs 时：**当轮内容外发**；UI 明确提示
- 无账号、无云同步、无 telemetry（v1.0）

### 7.3 离线

- 无网络：书库全流程可完成（Ollama 本地）；深聊退化为仅文档模式
- 无 Ollama：可浏览书库与原文；AI 功能不可用

### 7.4 体验验收

| 指标 | 目标 |
|------|------|
| 新用户 onboarding | 首次 spotlight 可跳过；激活路径仍为导入 → 打开 → 摘要 |
| Citation 跳转 | 1 次点击 |
| 内部美观评审 | ≥4/5 |

### 7.5 模型档位（默认推荐）

| 系统内存 | 推荐模型 |
|----------|----------|
| ≥18GB | `qwen3.5:9b` |
| ≥10GB | `qwen3.5:4b` |
| 4–8GB | `qwen3.5:0.8b`（能力受限，需 UI 提示） |

## 附录 A：术语表

| 术语 | 定义 |
|------|------|
| **段（Segment）** | 智能分段后的阅读单元；RAG / citation 最小粒度 |
| **段摘要** | LLM 对单段生成的三句话 + 结构化要点 |
| **段标签（label）** | 段摘要的浓缩一行（≤20 字）；分组后的段列表第一行用此字段；笔记 / 深聊仍用此字段 |
| **段列表行标题** | 第一行 `段 N · 标题`：分组后用 `label`；无结构平铺时优先 `chapter`，否则 `label` |
| **深聊** | 可唤起的段级对话区（底部抽屉）；文档 + 联网联合回答 |
| **Prefetch** | 后台预生成后续段摘要 |
| **摘要版** | 用户导出的合并 Markdown 文档 |
